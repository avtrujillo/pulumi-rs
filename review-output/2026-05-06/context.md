# SDK Review: `context`

**Date:** 2026-05-06  
**Rust file:** `pulumi-core/src/context.rs`  

---

## Summary

The Rust `context.rs` covers the core settings parsing and typed config access adequately, but is missing substantial infrastructure that the other three SDKs all share: engine capability negotiation and caching, a `Config` namespace class, secret-Output config variants, RPC lifecycle tracking for clean shutdown, and several context accessor methods. The implementation is usable for simple programs but will break down in production scenarios that rely on feature gating, secret config outputs, or graceful teardown.

---

## Missing Features

### 1. Feature Capability Negotiation and Caching

All three upstream SDKs query `SupportsFeature` at startup and cache the results as boolean flags. These flags gate entire code paths.

**Go** (`NewContext`): Queries 10 features synchronously at construction time, caches as fields on `contextState`:
```go
keepResources            // "resourceReferences"
keepOutputValues         // "outputValues"
supportsDeletedWith      // "deletedWith"
supportsReplaceWith      // "replaceWith"
supportsAliasSpecs       // "aliasSpecs"
supportsTransforms       // "transforms"
supportsInvokeTransforms // "invokeTransforms"
supportsParameterization // "parameterization"
supportsResourceHooks    // "resourceHooks"
supportsErrorHooks       // "errorHooks"
```

**Node.js** (`awaitFeatureSupport()`): Queries 11 features (adds `"secrets"`) via `Promise.all` and stores on `store`.

**Python** (`_load_monitor_feature_support()`): Same 11 features via `asyncio.gather`, cached in `SETTINGS.feature_support` dict.

**Rust**: Has only an internal `pub(crate) async fn supports_feature(&self, feature: &str)` that issues a live gRPC call every time. No caching, no startup negotiation, no exposed boolean flags. This means resource serialization (`keepResources`), alias handling, transform support, and hook support are all unguarded.

### 2. `Config` Namespace Class

Go (`config/get.go`), Node.js (`config.ts`), and Python (`config.py`) all provide a `Config` struct/class that:
- Accepts a namespace (defaults to project name)
- Automatically qualifies bare keys as `namespace:key` via `ensureKey`/`fullKey`/`full_key`
- Has instance methods for all typed getters/requirers

**Go** also exposes module-level functions (`Get`, `GetBool`, `GetInt`, `GetFloat64`, `GetObject`, `Require*`) that accept a `*Context` and apply `ensureKey` transparently.

**Rust**: Only flat methods on `Settings`/`Context` requiring fully qualified keys (`"app:region"`). A user who passes just `"region"` gets `None` silently instead of the correct auto-qualified lookup.

### 3. Secret Output Config Variants

All three upstream SDKs have symmetric "secret" variants for every config getter/requirer that wrap the value in a secret `Output<T>`:

| Go | Node.js | Python | Rust |
|---|---|---|---|
| `GetSecret(ctx, key) StringOutput` | `getSecret(key) Output<K>` | `get_secret(key) Output[str]` | ❌ |
| `GetSecretBool(ctx, key) BoolOutput` | `getSecretBoolean(key) Output<bool>` | `get_secret_bool(key) Output[bool]` | ❌ |
| `GetSecretInt(ctx, key) IntOutput` | `getSecretNumber(key) Output<number>` | `get_secret_int(key) Output[int]` | ❌ |
| `GetSecretFloat64(ctx, key) Float64Output` | `getSecretNumber(key)` | `get_secret_float(key) Output[float]` | ❌ |
| `GetSecretObject(ctx, key, out) Output` | `getSecretObject<T>(key) Output<T>` | `get_secret_object(key) Output[Any]` | ❌ |
| `RequireSecret(ctx, key) StringOutput` | `requireSecret(key) Output<K>` | `require_secret(key) Output[str]` | ❌ |
| `RequireSecretBool`, `RequireSecretInt`, `RequireSecretFloat64`, `RequireSecretObject` | same pattern | same pattern | ❌ |

Without these, code generated by `pulumi-codegen` for secret config inputs cannot be expressed correctly.

### 4. RPC Lifecycle Management

**Go**: `beginRPC()`/`endRPC(err)` increment/decrement an outstanding-RPC counter; `wait()` drains the WaitGroup and all pending RPCs before shutdown.

**Node.js**: `rpcKeepAlive()` returns a done callback; `waitForRPCs()` chains promises; `disconnect()`/`disconnectSync()` tears down connections.

**Python**: `RPCManager` tracks outstanding async operations; `SETTINGS.rpc_manager` field.

**Rust**: No RPC tracking. `Context` has no `close()`, `wait()`, or connection teardown. Programs can exit before in-flight resource registrations complete.

### 5. `require_pulumi_version` / `RequirePulumiVersion`

**Node.js**: `requirePulumiVersion(range: string): Promise<void>` calls `engine.requirePulumiVersion`.

**Python**: `require_pulumi_version(rg: str)` calls `engine.RequirePulumiVersion`.

**Go**: Implicit via `RegisterPackage` feature gating.

**Rust**: Absent entirely.

### 6. `legacy_apply_enabled` / `PULUMI_ENABLE_LEGACY_APPLY`

Node.js `isLegacyApplyEnabled()` and Python `is_legacy_apply_enabled()` read `PULUMI_ENABLE_LEGACY_APPLY`. Rust does not parse this environment variable and has no corresponding field or method.

### 7. `PULUMI_DISABLE_RESOURCE_REFERENCES`

**Go**: `var disableResourceReferences = cmdutil.IsTruthy(os.Getenv("PULUMI_DISABLE_RESOURCE_REFERENCES"))` is checked on every `RegisterResource`, `Invoke`, `ReadResource`, and `Call` to set `AcceptResources` on the gRPC request.

**Rust**: Absent; `AcceptResources` cannot be disabled.

## Behavioral Divergences

### 1. `organization()` Default Value

**Go** (`Organization()`):
```go
if org == "" {
    org = "organization"
}
return org
```
Returns the sentinel string `"organization"` when the organization is unset.

**Rust** (`organization()`):
```rust
pub fn organization(&self) -> &str {
    &self.settings.organization
}
```
Returns `""`. This diverges from Go's contract and will break any downstream code that relies on the non-empty default (e.g., URN construction that embeds the org).

### 2. `is_config_secret` Lookup Complexity

**Rust** uses `Vec::contains` for O(n) linear scan:
```rust
pub fn is_config_secret(&self, key: &str) -> bool {
    self.config_secret_keys.contains(&key.to_string())
}
```
Additionally, `key.to_string()` allocates on every call. All other SDKs check membership via iteration or set lookup but do not allocate. Minor but worth noting.

### 3. Config Error Granularity

**All upstream SDKs** propagate `config.Require*` failures as panics (Go), thrown errors (Node.js), or typed exceptions (Python) with structured messages including the full key and a hint to run `pulumi config set`.

**Rust** `require_config` returns `Error::Custom(format!("missing required config: {key}"))`. The message omits the actionable hint (`pulumi config set <key> <value>`) and uses a generic `Error::Custom` variant with no structured key field, making programmatic error handling and user-facing messages worse.

### 4. `Settings::from_env()` Missing `PULUMI_ROOT`

**Go** `RunInfo` has `RootDirectory` (the `Pulumi.yaml` location). **Node.js** reads `rootDirectory` from settings. **Python** reads `root_directory` from environment or `Settings` constructor.

**Rust** `Settings::from_env()` does not parse this environment variable at all.

### 5. `parallel()` Not Exposed on Context

Go exposes `ctx.Parallel() int32`. Node.js exposes `options().parallel`. Python exposes `SETTINGS.parallel`. Rust has `Settings.parallel: i32` but no `Context::parallel()` accessor, leaving callers without a way to read the concurrency setting.

## Recommendations

### P0 — Blocks Correctness

1. **Feature capability caching at startup.** Add a `FeatureSupport` struct with boolean fields for all 11 features. Call `supports_feature` for each during `Context::new()` (or lazily with `OnceCell`). Gate `keepResources`, `keepOutputValues`, and `supportsAliasSpecs` in resource/invoke builders. Without this, gRPC requests will be malformed against newer and older engines alike.

2. **Fix `organization()` default.** Return `"organization"` (not `""`) when `PULUMI_ORGANIZATION` is unset, matching Go's `Organization()` contract. This affects URN construction.

3. **Secret Output config variants.** Add `get_config_secret`, `get_config_secret_bool`, `get_config_secret_int`, `get_config_secret_float`, `get_config_secret_object` (and `require_*` variants) returning `Output<T>` marked as secret. Required for any program that reads secret config values.

### P1 — Significant Usability Gaps

4. **`Config` namespace struct.** Implement `Config::new(name: Option<&str>)` that defaults to `ctx.project()`, stores the prefix, and delegates to `ctx.get_config(format!("{prefix}:{key}"))`. Without this, programs migrated from Go/Node.js/Python silently get `None` for bare keys.

5. **Add `root_directory` to `Settings`.** Read `PULUMI_ROOT` in `from_env()`. Expose `Context::root_directory() -> &str`. Required for provider resolution and file-relative paths.

6. **Add `parallel()` to `Context`.** Expose `Settings::parallel` via `Context::parallel() -> i32`.

7. **Structured config error types.** Replace `Error::Custom(format!(...))` in config methods with `ConfigMissingError { key }` and `ConfigTypeError { key, value, expected }` variants on `Error`. The error messages should include the `pulumi config set` hint.

### P2 — Completeness / Cross-SDK Parity

8. **`require_pulumi_version(range: &str)`** — call `engine.RequirePulumiVersion` with the semver range string; return `Error::EngineError` if `UNIMPLEMENTED`.

9. **`running_with_mocks()` method.** `Context::running_with_mocks() -> bool` — return `true` when the monitor/engine are mock implementations. Can be implemented as a marker on the `MonitorConnection` trait.

10. **`legacy_apply_enabled`** — read `PULUMI_ENABLE_LEGACY_APPLY` in `Settings::from_env()`, expose `Context::is_legacy_apply_enabled() -> bool`.

11. **`PULUMI_DISABLE_RESOURCE_REFERENCES` support** — parse in `Settings::from_env()`, thread into `AcceptResources` fields on all gRPC requests.

12. **RPC lifecycle / connection teardown** — implement `Context::close()` that shuts down gRPC connections; add a completion barrier (e.g., `Arc<AtomicUsize>` counter + `Notify`) for in-flight registrations so `run()` can await clean shutdown.

---

## Verdict

**SIGNIFICANT GAPS**

The Rust `context` module has a sound foundation for config access and basic context metadata, but is missing the engine capability negotiation layer (feature caching), the `Config` namespace class, all secret-Output config variants, connection lifecycle management, and several context accessors present across all three upstream SDKs. These gaps will cause correctness issues (wrong wire format for resources), silent behavioral differences (bare config keys silently miss), and inability to express secret config values as `Output<T>`.
